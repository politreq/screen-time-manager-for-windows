# План проекта: родительский контроль для Windows и Android

## Цель и исходная база

Развивать аналог Kaspersky Safe Kids: родитель задаёт ограничения, детское
устройство учитывает использование и применяет правила, родитель получает отчёты.
Первый MVP: суточные лимиты, расписание, дополнительное время и отчёт за день
на Windows и Android. Фильтрация сайтов, геолокация и геозоны — следующие этапы.

Исходник: https://github.com/spamsch/screen-time-manager-for-windows

Проверенная версия: `1.0.40`, commit
`26f6cf54d22e288506aa4b6ea211444cc8e1b3ba`. Лицензия MIT.

Уже есть Windows-интерфейс на Win32, SQLite, недельные лимиты, экран блокировки,
паузы, определение простоя и Telegram-команды. В репозитории нет Android-клиента,
семейных аккаунтов или сервера управления устройствами.

## Что необходимо исправить в исходной архитектуре

1. `src/database.rs` сохраняет PIN в открытом виде и создаёт PIN `0000`.
   Нужны обязательная первичная настройка, хеширование с солью, ограничение
   попыток, миграция существующих записей и восстановление доступа родителя.
2. `src/main.rs`, интерфейс и часть хранения используют Windows API напрямую.
   Перед переносом выделить правила времени в отдельную библиотеку без Win32.
3. `install.ps1` создаёт интерактивную задачу с ограниченными правами.
   Это не основание обещать защиту от завершения процесса или изменения данных.
   Спроектировать Windows-службу, права доступа и связь службы с UI.
4. `.github/workflows/release.yml` публикует релизы при push в `release`.
   Для форка сначала настроить проверку Windows-сборки на PR и отдельный выпуск.

## Предлагаемая архитектура

- **Общее Rust-ядро:** правила, расписания, учёт времени, дополнительные минуты,
  версии политик и события. Хранение и системные вызовы через платформенные адаптеры.
- **Windows:** служба учёта/применения правил и отдельный интерфейс пользователя.
  Административные операции проверяются службой; правила работают без сети.
- **Android:** клиент на Kotlin с нативными Android API; общая Rust-библиотека
  подключается через JNI после стабилизации её интерфейса. Разрешения на статистику,
  фоновые операции и механизмы ограничения требуют отдельного прототипа.
- **Управление семьёй:** семейные аккаунты, привязка устройств, роли, доставка
  версионированных правил, отчёты и запрос дополнительного времени.
  Конкретный серверный стек выбрать после первого прототипа.

Обычная установка APK и режим управляемого устройства имеют разные возможности.
До выбора режима проверить на реальных устройствах, какие ограничения доступны;
не обещать полную защиту от удаления приложения или отключения разрешений.
Родительское управление и детский режим должны явно показывать свои роли.

## Этапы и критерии готовности

### 1. Подключение форка и воспроизводимая Windows-сборка

Создать форк, подключить его в Codex, добавить Windows CI для PR.
Готовность: проверка и сборка проходят на Windows; существующие сценарии
лимитов, PIN, пауз и перезапуска проверены на тестовом ПК.

### 2. Защита настроек и выделение общего ядра

Исправить PIN и миграцию, определить правила времени, выделить Rust-библиотеку.
Готовность: проверены исчерпание лимита, полночь, часовой пояс, перезапуск,
перевод часов, паузы и выдача дополнительных минут; Windows использует это ядро.

### 3. Прототип Android и проверка ограничений

Создать Android-проект; проверить статистику использования, фоновые ограничения,
экран лимита и необходимые разрешения. Выбрать минимальную версию Android
и поддерживаемые режимы установки по результатам прототипа.
Готовность: debug APK собран, установлен и проверен на физическом устройстве;
снятие разрешений и перезагрузка дают объяснимое состояние в интерфейсе.

### 4. Семейный MVP

Добавить безопасную привязку, родительский интерфейс, синхронизацию правил,
отчёт за день и запрос дополнительных минут.
Готовность: родитель управляет Windows и Android; без сети сохраняются последние
правила; после восстановления связи события синхронизируются без дублей.
Команды авторизованы, защищены от повторного применения и привязаны к устройству.

### 5. Расширение возможностей

Лимиты отдельных приложений, фильтрация сайтов, геолокация/геозоны,
уведомления, подписанные установщики, обновления и политика хранения данных.
Каждую функцию выпускать после проверки платформенных ограничений и восстановления
доступа. Не собирать личные данные, не необходимые для выбранных функций.

## Как завершить подключение

Форк создан. В рабочей копии `origin` указывает на форк `politreq`, а `upstream`
на исходный репозиторий `spamsch`.

В Codex Cloud выбрать `politreq/screen-time-manager-for-windows` как репозиторий
нового окружения. Для облачной разработки установить Rust; Windows-сборку
выполнять на Windows runner. Чтобы инструкции действовали на основной ветке,
объединить подготовительную ветку через pull request.

Текущая ветка содержит только подготовительные документы. Следующая конкретная
задача: Windows CI и обязательная настройка защищённого PIN с миграцией базы.
